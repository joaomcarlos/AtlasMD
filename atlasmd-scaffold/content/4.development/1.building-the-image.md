# Building the Image

The AtlasMD image is published to GHCR automatically on push to main. Build it locally when you need to test renderer changes before publishing.

## 1. Prerequisites

- Docker

## 2. Build

Build the image from the renderer directory:

::snippet{:content='["cd atlasmd-renderer", "docker build -t ghcr.io/joaomcarlos/atlasmd:latest ."]'}
::

This produces the `ghcr.io/joaomcarlos/atlasmd:latest` image locally. Pushes to `main` publish it to GHCR automatically via the GitHub Actions workflow.

## 3. What the Dockerfile Does

::side-note
Dockerfile steps
::

The Dockerfile lives at `atlasmd-renderer/Dockerfile`. Read it directly for the exact steps. In summary:

1. Installs Node dependencies (yarn, cached)
2. Applies a build-time patch to pinceau — replaces random `nanoid(6)` variant class names with deterministic hashes, fixing SSR hydration mismatches
3. Copies the renderer source
4. Creates empty `content/` and `public/` mount points — consumer projects fill them at runtime via volume mounts

## 4. Dev Mode

::side-note
Why dev mode
::

The image runs Nuxt in dev mode (`nuxi dev`). This is intentional: Docus prerenders content at build time, but content is mounted at runtime. Dev mode serves runtime-mounted content without requiring a rebuild.

## 5. Rebuilding After Changes

When you change the renderer source (components, config, CSS, plugins), rebuild the image:

::snippet{:content='["cd atlasmd-renderer", "docker build -t ghcr.io/joaomcarlos/atlasmd:latest ."]'}
::

Consumer projects pick up the new image on their next `docker compose up`.
