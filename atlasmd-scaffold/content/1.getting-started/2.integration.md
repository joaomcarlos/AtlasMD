# Integration Guide

This guide shows how to add AtlasMD documentation to your own project.

## Prerequisites

- Docker and Docker Compose
- The `atlasmd:latest` image built from this repository

::note
Build the image first: `cd atlasmd-renderer && docker compose build`
::

## Step 1: Copy the Scaffold

Copy the `atlasmd-scaffold/` folder into your project. Rename it to whatever makes sense for your project (e.g. `docs/`).

```bash
cp -r /path/to/AtlasMD/atlasmd-scaffold /path/to/your-project/docs
```

## Step 2: Reference the Compose File

In your project's main `docker-compose.yml`, include the scaffold's compose file:

```yaml
include:
  - docs/docker-compose.yml
```

Alternatively, define the service directly in your main compose file. See the scaffold's `docker-compose.yml` for the template.

## Step 3: Configure AtlasMD

Edit the scaffold's `config.toml` and set the values for your project:

```toml
title = "MyProject"

[[socials]]
url = "https://git.example.com/group/my-project"
label = "View MyProject on GitLab"
icon = "simple-icons:gitlab"
```

See [Configuration](/configuration/overview) for the full list of fields. Logos are convention-based — drop `logo-light-mode.png`, `logo-dark-mode.png`, and `logo-dark-mode-bg.png` into `public/` (no config needed).

## Step 4: Add Your Content

Write markdown files in `content/` following the content conventions:

- `1.Title.md` filename format (numeric prefix + dot + title)
- `_dir.yml` in each directory for navigation metadata
- Icons only in top-level `_dir.yml` files
- MDC syntax for rich content (`::note`, `::side-note`, custom components)

## Step 5: Add Your Assets

Place favicons and logos in `public/`. These are served at the root URL path. Logos use fixed filenames: `logo-light-mode.png`, `logo-dark-mode.png`, and `logo-dark-mode-bg.png`.

## Step 6: Run

```bash
docker compose up
```

Open the configured port in your browser. The default scaffold uses port 47145.

## Path Adjustments

If you placed the scaffold in a subdirectory, adjust the volume mount paths in the compose file. The paths must be relative to your main `docker-compose.yml` location.

```yaml
volumes:
  - ./docs/content:/app/content
  - ./docs/public:/app/public
  - ./docs/config.toml:/app/config.toml
```

## Build Context

The scaffold's `docker-compose.yml` references the AtlasMD image. Two options:

1. **Pre-built image**: Build `atlasmd:latest` from the `atlasmd-renderer/` folder once. Consumer projects pull the image.
2. **Build from source**: Set the build context to point at your AtlasMD checkout. The compose file in the scaffold uses this approach with a relative path — adjust it to match your directory layout.
