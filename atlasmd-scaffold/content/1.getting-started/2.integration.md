# Integration Guide

AtlasMD is a documentation rendering engine sealed inside a Docker image. You mount your markdown content, static assets, and a TOML config file — it serves a themed, searchable, dark-mode-ready documentation site. No Node.js, no build pipeline, no JavaScript tooling.

## 1. Overview

This guide shows how to add AtlasMD documentation to your own project. You will copy a single Docker Compose file, configure your project title and branding, and add markdown files. Docker pulls the AtlasMD image and serves your content.

The AtlasMD image lives at `ghcr.io/joaomcarlos/atlasmd:latest`. It contains the full rendering engine: Nuxt, Docus, Vue components, CSS, plugins. Your project only needs to provide markdown content, static assets, and a TOML config file. The image reads them at startup and serves the documentation site.

What you need:

- Docker and Docker Compose
- Markdown content for your documentation
- A source app icon for logos and favicons (any size, any reasonable format)

## 2. Getting It Running

AtlasMD runs as a single Docker service. You provide a compose file that pulls the image and mounts three paths from your project into the container:

### 2.1. The Compose File

Copy the `compose.yml` from `atlasmd-scaffold/` into your project. It pulls `ghcr.io/joaomcarlos/atlasmd:latest` from GHCR.

The compose file mounts three paths from the same directory as the compose file:

| Host path       | Container path     | Purpose                                              |
| --------------- | ------------------ | ---------------------------------------------------- |
| `./content/`    | `/app/content`     | Markdown files and `_dir.yml` navigation configs     |
| `./public/`     | `/app/public`      | Favicons, logos, static images                       |
| `./config.toml` | `/app/config.toml` | Consumer configuration (title, social links, footer) |

### 2.2. Ports

The scaffold exposes two ports:

| Port  | Container | Purpose                            |
| ----- | --------- | ---------------------------------- |
| 47145 | 47145     | Web server (HTTP)                  |
| 47146 | 4000      | HMR websocket (content hot reload) |

Adjust the left side of each port mapping in `compose.yml` if you need different host ports.

## 3. Configuration

AtlasMD reads consumer configuration from a TOML file mounted at `/app/config.toml`. Every consumer-configurable setting lives in this one file — no environment variables needed for consumer config. Only CI/build-driven values stay as environment variables: `CI_PAGES_URL` (GitLab CI), `APP_VERSION` (build arg), and `PORT`.

### 3.1. The Config File

::side-note
Config file
::

Edit `config.toml` next to the compose file.

Key Fields:

- **title** — Project name in header and browser title
- **baseUrl** — Base URL path (for GitLab Pages subpaths); `CI_PAGES_URL` overrides this at deploy time
- **socials** — One `[[socials]]` block per link, each with `url`, `label`, and `icon` (an Iconify icon name)
- **footer.credits** — Credits text, link, and icon in the footer
- **footer.text** — Footer text link label and URL; omit to hide

See [Configuration](/configuration/overview) for the full field reference.

::note
You can add more social links by adding more `[[socials]]` blocks to the config file. Each block requires `url`, `label`, and `icon`.
::

### 3.2. Branding Assets

AtlasMD picks up logos and favicons by filename convention — no config entry needed. Drop these files into `public/`:

| Theme state               | Filename                |
| ------------------------- | ----------------------- |
| Light mode                | `logo-light-mode.png`   |
| Dark mode                 | `logo-dark-mode.png`    |
| Dark mode with background | `logo-dark-mode-bg.png` |

Plus the favicons: `favicon.ico`, `favicon-16.png`, `favicon-32.png`.

The `Logo.vue` component renders the correct logo based on the active theme. The favicons are declared in `nuxt.config.ts` and served at the root URL.

### 3.3. Generating Assets with AI Skills

AtlasMD ships AI skills that generate all logos and favicons from a single source icon. The `atlasmd-icons` skill takes any source image, removes the background, and produces every correctly-sized asset AtlasMD expects in `public/`.

First, install the skills into your docs directory so your AI agent can load them. Copy and paste this prompt to your AI agent:

::ai-prompt
Copy the ai/skills/ directory from the AtlasMD repository into the docs directory of this project. Then read ai/AGENTS.md and follow its instructions for loading the atlasmd-icons and atlasmd-docs skills.
::

Then generate the assets. Copy and paste this prompt to your AI agent:

::ai-prompt
Load the atlasmd-icons skill and generate all AtlasMD logos and favicons from the source icon at assets/app-icon.png. Output them into the public/ directory.
::

The skill runs a Python script via `uv run` that handles background removal, tight-cropping, and resizing. No manual image editing needed.

## 4. Content Organization

Write markdown files in `content/` following the AtlasMD content conventions. The structure is deterministic — the file numbering controls navigation order, the directory structure controls the sidebar.

### 4.1. File Naming

Use the `N.Title.md` format:

- The number controls navigation order
- The text after the dot becomes the page title
- `0.index.md` in a directory becomes the section landing page

Example:

- `1.overview.md` — first page, titled "Overview"
- `2.architecture.md` — second page, titled "Architecture"
- `0.index.md` — landing page for the section

Do not use `N-Title.md` (hyphen). Docus uses the dot separator for its ordering system.

### 4.2. Directory Structure

Organize content into numbered top-level sections. Each directory has a `_dir.yml` file for navigation metadata (title, description, icon, redirect). Include `icon` only in top-level `_dir.yml` files.

The standard layout:

- **content/**
  - **0.index.md** — landing page
  - **1.getting-started/** — orientation
  - **2.understanding/** — conceptual deep-dive
  - **3.api-reference/** — contract reference
  - **4.integrations/** — per-system integration pages
  - **5.development/** — config, testing, deployment
  - **6.additional-resources/** — learn-more section (optional)
  - **8.release-notes.md** — changelog

Leave a numbering gap between the last regular section and release notes so you can insert new sections without renumbering.

### 4.3. MDC Syntax

AtlasMD supports Markdown Components (MDC) for rich content:

- `::note` — highlighted callout box for important clarifications
- `::side-note` — text in the marginalia column
- `::fig` — image with dark/light mode variants and click-to-zoom
- `::field` — API field definition with name, type, and required marker
- `::simple-card` — bordered card for grouping content
- Mermaid code blocks — interactive SVG diagrams with click-to-zoom

See [Content Conventions](/configuration/content-conventions) for the full rules and [Building Blocks](/building-blocks/note) for live-rendered examples of every component.
