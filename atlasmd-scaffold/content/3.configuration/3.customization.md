# Customization

AtlasMD separates consumer configuration (in `config.toml`) from renderer internals (in the Docker image). This page covers what consumer projects can customize without rebuilding the image, and what requires a renderer change.

## 1. Logos

Logos are convention-based. Drop these files into `public/` and AtlasMD picks them up automatically — no configuration needed:

| Theme state               | Filename                |
| ------------------------- | ----------------------- |
| Light mode                | `logo-light-mode.png`   |
| Dark mode                 | `logo-dark-mode.png`    |
| Dark mode with background | `logo-dark-mode-bg.png` |

The `Logo.vue` component renders the correct logo based on the active theme.

## 2. Theme and Colors

Theme tokens live in `atlasmd-renderer/tokens.config.ts`. To change colors, typography, or spacing, modify that file and rebuild the image.

::note
Theme changes affect all consumer projects. If you need project-specific theming, fork the renderer or open a discussion about adding config-driven theme overrides.
::

## 3. Social Links

Social links are config-driven — each consumer adds `[[socials]]` blocks to `config.toml` with a `url`, `label`, and `icon` (an Iconify[^1] icon name like `simple-icons:github` or `simple-icons:slack`).

To add or remove social links, edit `config.toml`. No renderer changes needed.

## 4. Footer

The footer is config-driven — each consumer sets its own text and links via the `[footer]` section of `config.toml`.

To change footer text or links, edit `config.toml`. To change the footer's structure (layout, number of link columns), edit `atlasmd-renderer/app.config.ts` and rebuild the image.

## 5. CSS

Base styles live in `atlasmd-renderer/assets/css/`. The image CSS handles `<DarkLightModeImage>` rendering. The base SCSS handles typography, tables, marginalia, and layout.

To add project-specific CSS, consumer projects can include custom components in their content using MDC syntax.
